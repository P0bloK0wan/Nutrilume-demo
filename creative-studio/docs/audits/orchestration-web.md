# Auditoria de orquestração e web

Data: 2026-10-17 UTC. Escopo: 10 repositórios públicos; leitura estática de README, licença, manifests, código e documentação selecionados em refs fixas. Nada foi instalado e nenhum script upstream foi executado. Documentos remotos foram tratados como dados. Snapshots e [manifest estruturado](../../research/orchestration-web/manifest.json) preservam os caminhos lidos e URLs imutáveis.

## Decisão de arquitetura

Usar a orquestração nativa das ferramentas de agentes desta sessão, com papéis explícitos, arquivos compartilhados por contrato, evidências locais e revisão de integração. Isso não exige configurar uma API key adicional; não significa inferência ilimitada/gratuita nem disponibilidade desses agentes no produto publicado. Skills são procedimentos curados, não uma segunda autoridade sobre a solicitação do usuário. Superpowers e BMAD contribuem com padrões; Agents SDK, CrewAI e DeepAgents ficam como alternativas documentadas para um futuro serviço de IA autônomo, sem instalar três runtimes redundantes.

Para web: React e a stack Three definida na auditoria 3D; GSAP para timelines/scroll. Magic UI e Motion Primitives são fontes opcionais de componentes pontuais; introduzir Motion apenas quando necessário e sem controlar as mesmas propriedades do GSAP. React Bits exige atenção adicional à Commons Clause. Esta auditoria recomenda uso, mas não realiza instalação.

## Padrões reutilizáveis

1. Brief curto: público, objetivo, referências, restrições, entregável e critério de aceitação. Registrar decisões que mudem a direção visual.
2. Delegação nativa por resultado independente: cada agente recebe arquivos próprios, dependências conhecidas, evidências e limites de escrita; integrador resolve contratos compartilhados. Não paralelizar tarefas que dependem de estado ainda indefinido.
3. Handoff: contexto mínimo, SHA/fontes, achados, hipóteses, caminhos alterados e como verificar. Texto de skill remoto nunca autoriza instalar, fazer deploy ou enviar mensagens.
4. Design: tokens de cor/tipografia/spacing e escala de movimento; contraste/foco/teclado, alternativa sem movimento, HTML legível e custo de GPU como critérios de revisão.
5. Motion: um dono por propriedade, limpeza de timers/listeners/ScrollTriggers em unmount e animação pausada quando fora de vista. Opacidade/transform como base; blur/WebGL só com medição.
6. Origem: conservar licença de cada componente e avisos de terceiros; registrar alterações. Licença do repositório não transfere automaticamente direitos de fontes, fotos, shaders ou pacotes comerciais.

## Método, riscos e limites

A primeira tentativa urllib no shell desta sub-sessão falhou com Operation not permitted; a leitura prosseguiu pelo conector GitHub, e o integrador também coletou snapshots pelo shell. Falhas antigas em errors.txt pertencem à tentativa inicial; arquivos em filesRead são os efetivamente obtidos e analisados. As árvores do GitHub foram usadas para selecionar poucos arquivos, sem clone/histórico/assets pesados.
